# 第二章怪物数据检查 & 无怪物出现问题排查
**日期：** 2026-03-30
**需求：** 检查 Ch2（熔岩虚空）所有怪物 EnemyData.asset 数据是否正确；排查进入第二章无怪物出现的原因。

---

## 一、根本原因：两处注册缺失

游戏无怪物出现 = **EnemyData 从未被系统加载到**。原因是两处注册都缺失：

### 问题 1：EnemyDatabase.asset 未注册 Lava 系怪物（最关键）

`Assets/Resources/Data/EnemyDatabase.asset` 当前只有 **6 条**记录（全是第一章 Dark 系怪物）：
```
- Dark_Slime (type 0)
- Dark_Tank (type 1)
- Dark_Rusher (type 2)
- Dark_Drifter (type 3)
- Dark_EliteTank (type 5)
- Dark_EliteDrifter (type 6)
```

Wave 配置（Chapter02_01.asset）引用了 `enemyType: 7-13`，但这些类型在 EnemyDatabase 中不存在。
`EnemyDatabase.GetData(type)` 会返回 null，导致 `WaveManager` 跳过生成。

**解决方案（Unity Editor 操作）：**
打开 `EnemyDatabase.asset` 的 Inspector，向 `enemies` 列表中追加以下 7 个 asset：
| Asset 文件 | type 值 | EnemyType 枚举 |
|---|---|---|
| `Lava_Splitter.asset` | 7 | LavaSplitter |
| `Lava_Tank.asset` | 8 | LavaTank |
| `Lava_Exploder.asset` | 9 | LavaExploder |
| `Lava_Gunner.asset` | 10 | LavaGunner |
| `Lava_EliteSplitter.asset` | 11 | EliteLavaSplitter |
| `Lava_EliteExploder.asset` | 12 | EliteLavaExploder |
| `Lava_Puddle.asset` | 13 | LavaPuddle |

---

### 问题 2：EnemyPoolManager 未注册 Lava 系预制体

`GameScene.scene` 中的 `EnemyPoolManager` 组件当前 `enemyConfigs` 只有 **4 条**（Dark 系怪物 type 0-3）。

`EnemyPoolManager.Spawn(type)` 会找不到对应 Pool，直接 return null，不报错但没有任何怪物生成。

**解决方案（Unity Editor 操作）：**
在 `GameScene.scene` 中找到 `EnemyPoolManager` GameObject，向其 `enemyConfigs` 列表追加：
| type | 预制体 | prewarmCount 建议 | maxCount 建议 |
|---|---|---|---|
| LavaSplitter (7) | Lava_Splitter 预制体 | 15 | 60 |
| LavaTank (8) | Lava_Tank 预制体 | 5 | 20 |
| LavaExploder (9) | Lava_Exploder 预制体 | 10 | 40 |
| LavaGunner (10) | Lava_Gunner 预制体 | 3 | 10 |
| EliteLavaSplitter (11) | 可不加入 Pool（类比 EliteTank 独立实例化） | - | - |
| EliteLavaExploder (12) | 可不加入 Pool（类比 EliteDrifter 独立实例化） | - | - |
| LavaPuddle (13) | Lava_Puddle 预制体 | 10 | 30 |

> 注意：第一章的精英怪（type 5、6）也没有在 EnemyPoolManager 中注册，说明精英怪是独立 Instantiate 的。第二章的 type 11、12 精英怪同理，可以不加入 Pool，但需要确认 WaveManager/SpawnHelper 是否有对应处理逻辑。

## 二、EnemyData 数据问题

以下字段存在**明确错误**，需要修正：

### ❌ 问题 3：Lava_Puddle.asset - behaviorType 错误

```yaml
behaviorType: 0  # Chase（追击）—— 错误！熔岩水坑应该是静止的
```
**应改为：** `behaviorType: 2`（Stationary）
**枚举定义：** `EnemyBehaviorType.Stationary = 2`，对应代码注释"静止 - 不移动，作为地形障碍（熔岩水坑）"。

### ❌ 问题 4：Lava_Gunner.asset - behaviorType 错误

```yaml
behaviorType: 0  # Chase（追击）—— 错误！炮手应该进入屏幕后停驻射击
```
**应改为：** `behaviorType: 3`（RangedGunner）
**枚举定义：** `EnemyBehaviorType.RangedGunner = 3`，对应代码注释"远程炮手 - 进入屏幕后停留在上方，定时射击"。
> Gunner 的 `gunnerStopYPercent: 0.6`、`gunnerShootInterval: 8`、`gunnerProjectilePrefab` 已正确配置，只需把 behaviorType 改掉即可激活该逻辑。

### ❌ 问题 5：Lava_Puddle.asset - splitOnDeath 错误

```yaml
splitOnDeath: 1    # 错误！熔岩水坑不应该分裂
splitEnemyType: 0  # Slime（第一章黑油怪）
splitCount: 3
```
**应改为：** `splitOnDeath: 0`
水坑是地形障碍，被激光摧毁后应该直接消失，不生成任何子单位。

### ⚠️ 问题 6：Lava_Splitter & Lava_EliteSplitter - splitEnemyType 需要确认

两者均设置了 `splitEnemyType: 0`（= `Slime`，即**第一章黑油粘液怪**），这在熔岩章节中不合理。

| 怪物 | 当前 splitEnemyType | 分裂数量 |
|---|---|---|
| Lava_Splitter | 0 (Slime) | 3 |
| Lava_EliteSplitter | 0 (Slime) | 7 |

**需要确认意图**，可选方案：
- 若希望分裂后留下岩浆遮挡物 → 改为 `13`（LavaPuddle）
- 若希望分裂后产出更多自爆者 → 改为 `9`（LavaExploder）
- 若需要新增"小熔岩碎片"类型 → 扩展 EnemyType 枚举（需改代码）
