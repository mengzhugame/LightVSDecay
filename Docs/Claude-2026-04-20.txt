 《光与朽》微信小游戏上线反馈分析 & 迭代方案

 Context（背景）

 2026-04-20 游戏已上线微信小游戏平台。朋友圈和游戏同行给出了 15 条反馈（见 Docs/光与朽玩家反馈问题.txt），覆盖数值、系统、美术、UI
 四大类。用户需要先判断"是否该 2 天内紧急修补"，再决定如何进入下一版本迭代。

 ---
 问题 1：是否该 2 天内紧急修补？

 ✅ 用户决定：等 3 天留存数据再决定（2026-04-20 敲定）

 理由如下：

 ┌────────────────┬──────────────────────────────────────────────────────────────────┬────────────────────────────────────────────────┐
 │      维度      │                       紧急修补（2 天打包）                       │             等待 3 天留存（推荐）              │
 ├────────────────┼──────────────────────────────────────────────────────────────────┼────────────────────────────────────────────────┤
 │ 信号可信度     │ 主要是熟人+同行反馈（样本小、带情感偏见）                        │ 真实用户数据（样本大、客观）                   │
 ├────────────────┼──────────────────────────────────────────────────────────────────┼────────────────────────────────────────────────┤
 │ 研发性价比     │ 赶工修 Bug 往往引入新 Bug，且无法在 3                            │ 用数据判定是"体验问题"还是"赛道问题"           │
 │                │ 天内重塑留存曲线（那批用户已经被当前版本"劝退"了）               │                                                │
 ├────────────────┼──────────────────────────────────────────────────────────────────┼────────────────────────────────────────────────┤
 │                │ Feedback                                                         │ 若留存差 → 考虑转 IAA + 接广告 +               │
 │ 核心风险       │ #9（发行警告留存会很差）若属实，紧急修补无法救，反而浪费工期     │ 进入下一款，止损最优；若留存 OK → 按本文档的   │
 │                │                                                                  │ P0/P1 优先级做下一版本                         │
 ├────────────────┼──────────────────────────────────────────────────────────────────┼────────────────────────────────────────────────┤
 │ 微信小游戏特性 │ 审核+替换包体有摩擦，匆忙修补大概率命中审核延迟                  │ 顺势把下一版本做扎实                           │
 └────────────────┴──────────────────────────────────────────────────────────────────┴────────────────────────────────────────────────┘

 决策建议：

 1. 这 3 天：不要动代码主干。可以做 "零风险"的无代码准备——重看反馈、整理下一版本的 P0 清单（本文档下方已整理）、跑 BattleStatistics
 采集新一批数据。
 2. 第 4 天拿到留存数据后：
   - 次日留存 < 20% / 3日留存 < 8%：留存赛道失败。不要修补——接 IAA 广告（看广告拿体力/图纸 +
 复活已有），放置"长尾回本"，团队进入下款立项期。
   - 次日留存 20–35% / 3日 8–15%：有救但不算爆款。按下述 P0+P1 迭代，目标是第二个版本把留存翻倍。
   - 次日留存 > 35% / 3日 > 15%：玩法被验证了。按 P0+P1+P2 完整做，重点放在"让喜欢的人更喜欢"（深度化 + IAA 变现点）。

 ▎ 关键洞察：Feedback #9 说"前期无任何让玩家想看广告的计费点"——这是 IAA
 ▎ 小游戏的命门。即使留存好，也必须在下一版本把"体力/图纸付费点"往前提，否则留下来的玩家也变现不了。

 问题 2：下一版本迭代方案（按优先级排序）

 ▎ 原则：先救留存（前 3 分钟体验）→ 再救爽感（核心循环）→ 最后抛光。
 ▎ 每条都标注了对应的反馈编号、涉及文件、改动成本（★低 / ★★中 / ★★★高）。

 🔥 P0 - 前 3 分钟体验（直接关联留存，必须做）

 P0-1. 第一关卡通关时间压缩 50%+（反馈 #9，★）

 - 问题：发行明确指出 Ch1 太长，玩家进不到"培养界面"就流失
 - 方案：Ch1 从当前约 5–8 分钟压到 2–3 分钟（参考头部休闲游戏第一关时长）
   - 减少前 3 波的敌人数量 30%
   - 把 Ch1 BOSS 血量砍 40%
   - 第一次通关后强制进入主界面，展示"水晶塔升级/图纸/装备"等养成入口
 - 涉及文件：Assets/Scripts/Data/SO/ChapterConfig.cs 的 Ch1 SO、对应 WaveConfig SO
 - 改动成本：★（仅 SO 数值调整）

 P0-2. 护盾 / 血量 UI 新手引导标识（反馈 #8，★）

 - 问题：玩家分不清左边是护盾、右边是血量
 - 方案：首次进入战斗时，HUDPanel 左右两条显示 Tooltip："🛡护盾（优先承伤）"、"❤血量（见底即死）"，2 秒后淡出，只显示一次（存 PlayerPrefs
 标记）
 - 涉及文件：Assets/Scripts/UI/Panels/HUDPanel.cs
 - 改动成本：★

 P0-3. 复活后必给清屏 + 2 秒无敌（反馈 #3，★★）

 - 问题：付费/看广告复活后直接被怪物淹没，复活形同虚设 → 打击付费意愿
 - 方案：RevivePanel.RevivePlayer() 触发后：
   a. 屏幕范围内所有敌人一次性消灭（复用大招清屏逻辑）
   b. TurretController 进入 2 秒无敌状态（视觉上加光环）
 - 涉及文件：Assets/Scripts/UI/Panels/RevivePanel.cs、Assets/Scripts/Logic/Player/TurretController.cs
 - 改动成本：★★

 P0-4. 熔浆液不再堵死炮口（反馈 #2，★★）

 - 问题：LavaProjectile 物理阻挡激光，贴脸后玩家只能等死
 - 方案：三选一（推荐方案 A）
   - A. 贴近水晶塔时自动消散：LavaProjectile 距离塔 < 2m 时自毁并扣一次伤害（给反馈但不阻塞视野）
   - B. 激光命中熔浆液可摧毁它（增加激光穿透/蒸发判定）
   - C. 熔浆液只落在中远距离，不贴脸生成
 - 涉及文件：Assets/Scripts/Logic/Enemy/LavaProjectile.cs、Assets/Scripts/Logic/Enemy/LavaGunnerAI.cs
 - 改动成本：★★

 P0-5. 连锁反应技能描述文字修正（反馈 #5，★）

 - 代码真相（已验证）：ChainLightningManager.cs:497 公式为 baseDamage * (1-0.2)^bounceIndex，即每跳衰减
 20%（0.8→0.64→0.51…），不是"衰减至20%"。
 - 问题：当前 Tooltip 文案与实际逻辑的口语化理解有歧义
 - 方案：把技能描述改为精准表述："闪电传递至最多 N 个目标，每次跳跃后伤害降低 20%"（或附上第2、3跳的实际百分比示例）
 - 涉及文件：技能描述文本位于 Assets/Scripts/Data/SO/SkillDatabase.cs 或本地化文本表
 - 改动成本：★（纯文案）

 ⚔️ P1 - 核心爽感（留存若 OK，必做）

 P1-1. 自动索敌 + 作为付费点（反馈 #14、#15，★★★）

 - 问题：纯手动瞄准消耗玩家精力，长关卡容易疲劳；反馈明确提议"自动索敌作为付费点"
 - 方案：
   - TurretController 新增"自动瞄准"模式（扫描最近/血量最低敌人，平滑转向）
   - 付费/解锁策略：
       - 免费：每局前 30 秒免费自动瞄准（让玩家尝到甜头）
     - 付费点：看广告解锁本局"全程自动瞄准"，或图纸永久解锁"自动瞄准套件"
   - 体感上应保留手动微调可能（auto-aim 作为辅助，而非替代）
 - 涉及文件：Assets/Scripts/Logic/Player/TurretController.cs、Assets/Scripts/Logic/Player/LaserController.cs、UI 解锁面板
 - 改动成本：★★★

 P1-2. 激光长度可感知地变长（反馈 #15，★）

 - 当前：GameSettings.maxLaserLength = 15f，有 MAIN_LASER_LENGTH_CAP（激光长度上限系统已做）
 - 方案：
   - 基础 maxLaserLength 15f → 20f（提升 33% 视觉爽感）
   - Reflex 技能加成曲线整体上调
   - 注意：要同时校准 MAIN_LASER_LENGTH_CAP，否则顶到天花板
 - 涉及文件：Assets/Scripts/Data/SO/GameSettings.cs、Assets/Scripts/Logic/Player/LaserController.cs
 - 改动成本：★

 P1-3. 大招改造为"一键清屏"（反馈 #3、#15，★★★）

 - 问题：当前大招系统是"可升级技能"形式，无一次性释放的爆发感；玩家要的是"按下去屏幕炸了"的爽
 - 方案：
   - 新增独立大招按钮（屏幕右下，蓄力条 UI）
   - 按下后释放全屏清屏效果（所有非 BOSS 敌人即死，BOSS 扣 15% 血）
   - 蓄力条通过"击杀积累" + "看广告立即充满"（IAA 付费点）
   - 复用现有 ChainLightningManager 的视觉资源做爆发特效
 - 涉及文件：Assets/Scripts/Logic/Player/SkillEffectManager.cs、新增 UltimateController.cs、HUDPanel.cs（蓄力条UI）
 - 改动成本：★★★

 P1-4. 弹球怪下落速度加快（反馈 #7，★）

 - 问题：弹得太高、落得太慢 → 等待无聊
 - 方案：
   - 弹球怪 EnemyData.mass 上调（加速重力），或 Rigidbody2D.gravityScale 提高 50%
   - 或降低最大弹跳速度上限
 - 涉及文件：对应弹球怪的 EnemyData SO
 - 改动成本：★

 P1-5. 击杀怪有概率生成闪电球（反馈 #13，★★）

 - 问题：主角技能单调，不够割草（反馈 #11）
 - 方案：
   - 新增"闪电球"技能/词条：击杀怪有 X% 概率生成一个滞留 3 秒的闪电球，对周围 2m 内敌人每 0.5 秒激光传导一次
   - 复用 ChainLightningManager 的传导逻辑和美术
 - 涉及文件：Assets/Scripts/Logic/Player/ChainLightningManager.cs、SkillEffectManager.cs、新增 Pooling 条目
 - 改动成本：★★

 P2-1. 三个宝箱头顶显示差异标签（反馈 #4，★★）

 - 方案：宝箱生成时带头顶小图标（补给🟦 / 抽奖🟨 / 交易🟥），配一行文字（"补给：立即回血"/"抽奖：随机强化"/"交易：消耗资源换稀有"）
 - 涉及文件：Assets/Scripts/Logic/TacticalDrop/TacticalCrate.cs、TacticalDropManager.cs
 - 改动成本：★★

 P2-2. 连锁反应闪电链美术替换（反馈 #12，★）

 - 方案：美术预制体已做好，只需替换 ChainLightningManager 的 VFX 引用
 - 涉及文件：Assets/Scripts/Logic/Player/ChainLightningManager.cs + Prefab 资源
 - 改动成本：★

 P2-3. 战斗场景水晶塔外观升级联动（反馈 #10，★★★ 含美术）

 - 现状澄清：装备界面的水晶塔会随品质换色图，但战斗场景中的水晶塔没有外观变化，且相应美术资源尚未制作
 - 方案：
   - 美术侧：委托美术出 5 档战斗场景水晶塔外观图（灰/绿/蓝/紫/橙），与装备界面调性统一
   - 代码侧：TowerAppearanceController.cs 已有装备品质联动架构，把 Sprite 数组绑到战斗场景塔的 SpriteRenderer
 即可（架构复用，无需新写逻辑）
   - 切换表现：装备升级瞬间，战斗塔加一层闪白+粒子爆散，然后切换新 Sprite（让玩家明确感知"我变强了"）
 - 涉及文件：Assets/Scripts/Logic/Player/TowerAppearanceController.cs、战斗场景塔 Prefab、5 张新美术图
 - 改动成本：★★★（等美术资源）；代码本身是 ★

 P2-4. 第一章怪物色差调整（反馈 #6，★★）

 - 问题：手机屏色域不同，怪物融入背景
 - 方案：
   - 最简：给 Ch1 怪物 SpriteRenderer 加 0.3f 的 outlineColor（白色或亮青描边）让其脱离背景
   - 或调整第一章背景亮度/饱和度，与怪物拉开对比度
 - 涉及文件：Ch1 怪物 Prefab（添加 outline shader）或场景背景 Sprite 调色
 - 改动成本：★★（偏美术）

关于第一关卡通关时间压缩 50%+，现在每一关都是10波次（9波怪+BOSS），总时间在10分钟左右。 如果要压缩到5分钟，是否需要把波次减少至5波（4波小怪+BOSS）？但是技能三选一需要玩家构建技能build，达到一定阶段才能有爽感。5分钟的时间，那就需要让玩家选择技能的频率翻一倍？
关于复活后必给清屏 + 2 秒无敌，我觉得也不必清屏，只需要给护盾一个冲击波效果（并且现在工程内已有），把小怪杀死，大怪推走就好。
关于大招改造为"一键清屏"，有个问题，如果是精英怪呢？如果是BOSS怪呢？所以大招改为一键清屏，爽感是有了，但是玩家通关会变的简单了，只要点击大招一键清屏就好。这样会对喜欢挑战有难度的玩家来说，简直无聊，就是点击放大招就完了。
关于主角技能单调的问题，他们表述的应该是只有激光攻击，这是弱点，但也是当初立项的目的，当初就是想做激光射击黑油，解压的休闲小游戏，所以没考虑除了激光，还有子弹，飞轮等，这样就和其它塔防游戏基本一样了，没有做出差异化。
关于自动索敌付费点设计，我同意你这样的设计。

关于第一关卡通关时间压缩 目前我自己测试下来感觉节奏还可以，现在是9波内会有17次升级（技能三选一），如果改为5波17次升级，玩家选择已经翻了一倍，是否对玩家来说有些太频繁？感觉boss血量不能降低了，再降低的话，遇到强力技能，boss还没释放几个技能，基本就被秒了，玩家毫无boss体验。 所以这个通关时间压缩的反馈是否是每个人的主观感受，不是实际结果？例如有的人觉得好玩，有的人觉得不好玩。不过也可以做一个简单版的新手引导关卡6波怪的，进行测试。
关于游戏爽感问题，有可能没有进行技能三选一的流派引导，导致有些玩家不知道点什么技能，随便点，才导致感觉不够爽。可以再第一波时添加对技能流派的引导。这样玩家构筑到强力技能，会体验到通关和割草的感觉。
