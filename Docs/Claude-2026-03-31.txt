  现状诊断

  WaveManager

  ---
  两种重构方案

  方案一：全部走 EnemyPoolManager（最简洁）

  所有怪物，包括精英和 Boss，都注册在 EnemyPoolManager，prewarmCount = 0, maxCount = 1。

  WaveManager 中删掉所有 prefab 字段，SpawnSingleEnemy 统一调用 EnemyPoolManager.Spawn(type, pos)。

  关于"池开销"的实际评估：
  ▎ prewarmCount = 0 时，池不预创建任何对象。第一次 Spawn() 时才 Instantiate（和现在完全一样）。Despawn() 时保留 1 个
  disabled 实例而不是 Destroy。
  ▎ 一个 disabled 的 GameObject 没有任何 Update 调用，内存开销约等于零，性能影响可以忽略。

  优点：改动最小，代码最干净，Inspector 统一管所有类型
  缺点：Boss 在 EnemyPoolManager 里配置略显奇怪（"Boss 的对象池" 语义不直觉）

  ---
  方案二：双轨制（推荐）

  将"怪物的管理策略"作为配置项，WaveManager 只认一个统一接口，内部自动路由。

  核心改动：
  1. EnemyPoolManager 的每条 config 增加一个 bool usePool 字段
    - usePool = true：走现有对象池逻辑（普通怪）
    - usePool = false：每次 Spawn → Instantiate，每次 Despawn → Destroy，没有池开销
  2. WaveManager 删掉所有散落的 prefab 字段，不再感知"怎么生成"
  3. Inspector 统一在 EnemyPoolManager 一处配置所有类型

  普通怪 (Slime / Exploder / ...):  usePool = true,  prewarm = 10, max = 50
  精英怪 (EliteLavaSplitter / ...): usePool = false, prefab → Instantiate/Destroy
  Boss:                              usePool = false, prefab → Instantiate/Destroy

  代码结构：
  EnemyPoolManager.Spawn(type, pos)
    ├── if config.usePool  → pool.Get()
    └── if !config.usePool → Instantiate(config.prefab)

  EnemyPoolManager.Despawn(enemy)
    ├── if config.usePool  → pool.Return()
    └── if !config.usePool → Destroy(enemy.gameObject)

  WaveManager：
  - 删除 bossPrefab, bossSpawnPoint, eliteTankPrefab, eliteDrifterPrefab
  - 删除 SpawnEliteEnemy()
  - SpawnSingleEnemy() 全部统一 → EnemyPoolManager.Instance.Spawn(type, pos)
  - Boss 波次仍然用 isBossWave 标记，位置用现有 bossSpawnPoint（这个可以保留，它是场景内的位置节点，不是预制体引用）

  优点：精英/Boss 真正零池开销，语义清晰，扩展性最好
  缺点：EnemyPoolManager 改动稍多（需要加 usePool 路由逻辑）

  4. Boss 的特殊战斗逻辑（血条、状态机切换）仍在 WaveManager 保留，只是生成调用统一走 EnemyPoolManager

熔浆液没有阻挡聚能透镜技能的激光穿透功能，需要阻挡激光穿透。

修复完成。涉及两个文件的最小改动：

  EnemyBlob.cs — 新增只读属性：
  public bool IsStationary => behaviorType == EnemyBehaviorType.Stationary;

  LaserController.cs — 穿透循环中，命中 Stationary 目标时 break 而非 continue：
  if (enemy.IsStationary)
      break;  // 不消耗穿透层数，直接截断

  为什么用 break 而非
  continue：穿透列表已按距离从近到远排序，熔浆液在激光路径上构成物理障碍，其后方的所有目标都应该被遮挡，所以直接终止整个穿透循环。若用
  continue，只会跳过这一个熔浆液，激光仍能打到后面的怪。
