 背景与问题

 当前 Frostcaster 设计的折磨感来源：
 - 进场→停驻→蓄力→召唤冰墙→换位→再蓄力（无限循环）
 - 冰墙随机位置生成，玩家无法通过操作控制其位置
 - 换位距离短（±2 格），施法者几乎原地不动
 - 精英版一次召唤 3~5 面，单次施法即可封锁全场
 - 结果：场景冰墙堆积 → 激光通道全堵 → 既打不到冰墙后的怪，又必须先清冰墙

 对比第二章熔岩（不折磨）的关键差异：
 - 岩浆由自爆怪死亡产生 → 玩家通过击杀位置控制岩浆在哪里（主动权在玩家）
 - 炮手火球可被激光打到（交互性）
 - 地形压迫来自怪物密度和时间压力，而非无限持续的静态障碍

 用户设计意向：
 1. 普通 Frostcaster → 射冰刺子弹（远程，可被激光拦截）
 2. EliteFrostcaster → 保留冰墙，但只施法一次，之后冲向光棱塔
 3. 保留冰墙的地形限制体验，但不让它无限堆积

     public static int ActiveCount => activeWalls.Count;
     public static void Register(EnemyBlob wall) => activeWalls.Add(wall);
     public static void Unregister(EnemyBlob wall) => activeWalls.Remove(wall);
     public static void DespawnOldest()
     {
         if (activeWalls.Count > 0 && activeWalls[0] != null)
             activeWalls[0].Deactivate(); // 走回池
     }
 }

 IceWall 的 EnemyBlob.OnSpawn() → 调用 IceWallTracker.Register(this)
 IceWall 的 EnemyBlob.OnDeactivate() → 调用 IceWallTracker.Unregister(this)

 （IceWall 是否已有 OnSpawn/OnDeactivate 回调需确认，应在 EnemyBlob.cs 中添加调用点）
