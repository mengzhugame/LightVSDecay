  根本原因：Unity / 团结引擎打 WebGL 包时，贴图压缩格式默认可能是 DXT（PC/桌面格式），但微信小游戏的 WebGL 环境不支持
  DXT，导致 GPU 无法解码贴图，渲染成黑色。

  ---

  第一步：看微信开发者工具控制台

  打开「调试器 → Console」，找类似这样的报错：
  WebGL: INVALID_VALUE: texImage2D: no ImageData, HTMLImageElement...
  GL_INVALID_OPERATION: Texture format not supported
  只要有 GL/贴图相关报错，就确认是格式问题。

  团结引擎编辑器里：
  Edit → Project Settings → Player → Other Settings → Texture Compression

  微信小游戏应选 ASTC 或 ETC2，不能用 DXT。

  选中 Project 面板里的 Sprite 贴图 → Inspector → Format，如果是 DXT1 / DXT5 / BC7 就是问题所在，改为 ASTC 6x6 或 ETC2

  ---
  根本原因分析

  原因一（主因）：Awake 里调用了 jslib，时机太早

  调用链：
  AdManager.Awake()
    → PreloadAllAds()         ← 如果 usePlaceholderAds=false
      → WeChatAdsPlugin.Instance  ← 创建新 GameObject
        → WeChatAdsPlugin.Awake()
          → WXAds_Init()      ← 调用 jslib，进入微信 JS 环境

  在 团结引擎 / 微信小游戏中，Awake 阶段游戏的 JavaScript 桥接还未完全就绪，这时调用 jslib 函数会导致 JS
  运行时异常，污染整个 WebGL 渲染上下文，造成黑屏。

  原因二（结构问题）：AdManager 不需要手动放进场景

  AdManager 是自创建单例——Instance getter 会自动 new GameObject 并
  DontDestroyOnLoad。你手动在场景里放了一个，等于在最危险的时机（渲染初始化之前）强制执行了 Awake。

  ---
  修复方案

  1. 把 PreloadAllAds() 从 Awake 改到 Start + 延迟一帧，确保微信 JS 桥接就绪后再初始化广告
  2. 从场景里删掉 AdManager 节点，让它按需自创建
  3. 广告位 ID 改用 Resources 里的 ScriptableObject 存，不依赖场景 Inspector
