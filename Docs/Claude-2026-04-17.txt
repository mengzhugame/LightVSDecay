 现在我已找到所有问题根源，分析如下：

  ---
  问题分析

  根本原因：WaitForSeconds vs 不受 timeScale 影响的 VFX

  PoolableVFX.cs:180:
  yield return new WaitForSeconds(cachedDuration);  // ← 受 Time.timeScale 影响

  EnemySteam 预制体配置了 useUnscaledTime: 1（使用真实时间播放），而 WaitForSeconds 是游戏时间。两者出现时间轴撕裂：

  ┌───────────────────────────┬──────────────────────────┬───────────────────────┬───────────────────────────────────┐
  │           情况            │         粒子播放         │       协程计时        │               后果                │
  ├───────────────────────────┼──────────────────────────┼───────────────────────┼───────────────────────────────────┤
  │ 开设置面板（timeScale=0） │ 粒子继续在真实时间里播完 │ 协程永久冻结          │ VFX 对象卡在 activeInstances      │
  │                           │                          │                       │ 里永不归还                        │
  ├───────────────────────────┼──────────────────────────┼───────────────────────┼───────────────────────────────────┤
  │ 再次暂停（累积）          │ 越来越多 VFX 卡住        │ pool 逐渐被占满到     │ 后续 PlayEnemySteam               │
  │                           │                          │ maxCount              │ 找不到可用实例 → 无特效           │
  └───────────────────────────┴──────────────────────────┴───────────────────────┴───────────────────────────────────┘

  为什么"第三章节明显"

  第三章节关卡更长、更难，玩家更频繁地打开设置面板暂停，导致池被耗尽的概率更高。一旦池满（50个实例全在
  activeInstances），所有后续死亡的敌人都拿不到 VFX。

  为什么"有时候"

  池是逐渐被耗尽的。前几波没问题（还有可用实例），但经过多次暂停后，池枯竭，从那一刻起全部无效。

  音效为什么也可能缺失

  PlayEnemyDeath() 有 enemyDeathCooldown 节流。大量敌人同时死亡（第三章 AoE
  技能触发）时，只有第一个会播放音效，后续被节流。

  ---
  修复：将 WaitForSeconds 改为 WaitForSecondsRealtime，与粒子系统的 useUnscaledTime 对齐。
